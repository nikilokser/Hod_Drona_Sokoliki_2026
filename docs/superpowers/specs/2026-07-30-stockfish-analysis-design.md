# Дизайн: интеграция Stockfish (v1)

Дата: 2026-07-30

## Контекст и цель

Третья и последняя из согласованных с пользователем крупных фич веб-морды
(после ленты переговоров и таймера хода/матча). Регламент **прямо запрещает**
использование шахматных движков, включая Stockfish, для выбора хода во время
зачётного матча (см. `CLAUDE.md`, «Ключевые ограничения регламента» — «шахматные
движки (Stockfish, Leela и т.п.) запрещены»). Стратегию и выбор хода обязаны
вырабатывать исключительно LLM-агенты.

Пользователь осознанно попросил интеграцию несмотря на этот риск, для двух
целей: (1) показ рекомендации движка в UI как визуальная подсказка оператору,
в том числе потенциально во время реального матча, и (2) тренировочный анализ
позиций/симуляция партий не на матче. Пользователь явно принял этот риск на
себя (см. обсуждение в диалоге); реализация обязана нести чёткую защиту от
случайного включения (см. «Защита включения» ниже) — это не переговоры о том,
разрешать ли фичу, а требование к её безопасной подаче.

**Важное упрощение, выявленное в ходе бренсторминга:** отдельного «режима
симуляции матча» не требуется. Stockfish никогда не двигает фигуры сам ни в
каком режиме — он только предлагает ход для той стороны, чья сейчас очередь
(одинаково что во время реального матча, что на тренировке); физическое
перемещение фигур мышкой пользователь всегда выполняет сам через уже
существующий drag-and-drop. Поэтому вся фича сводится к одному переключателю
«показывать рекомендацию Stockfish», а не к двум разным режимам работы поля.

## Область действия

Включено: определение «чей ход» для целей анализа (новое, отдельное от
`match_clock`), включение/выключение подсказки Stockfish с защитой, конвертация
доски в FEN, получение и отображение рекомендации (стрелка на доске + оценка).

Не входит в scope: автоматическое перемещение фигур движком, «режим
симуляции» как отдельная сущность (упразднён по итогам бренсторминга), пауза и
досрочное завершение матча (отдельная будущая задача по `match_clock`,
запрошена пользователем, но осознанно отложена до завершения этой фичи).

## «Чей ход» для анализа — новое состояние, отдельное от `match_clock`

`match_clock.active_color` (уже реализован) остаётся полностью ручным,
судейским полем только для отсчёта времени — эта фича его не трогает и не
меняет его семантику.

Для Stockfish нужен свой трекер: новый `app_state["side_to_move"]`
(`"white"` | `"black"`, по умолчанию `"white"`). Обновляется **автоматически**
после каждого успешного перемещения фигуры на доске через `POST /api/move`
(в `state.py` `apply_move` уже знает цвет двинутой фигуры — после успешного
хода `app.py` выставляет `side_to_move` в цвет, противоположный только что
походившей стороне). Плюс всегда доступный (не заблокированный ничем, включая
то, начат матч или нет) ручной переключатель поверх автоматики — на случай
если авто-определение разошлось с реальной позицией после серии ручных
правок в режиме `correct`.

## Защита включения

Переключатель «Stockfish» в UI, по умолчанию выключен (`app_state["stockfish_enabled"] = False`).
Попытка включить через клик → открывается уже существующий `confirmDialog`
с текстом, прямо ссылающимся на пункт регламента («Регламент запрещает
использование шахматных движков для выбора хода во время зачётного матча.
Включить подсказку Stockfish только для анализа/тренировки?») → подтвердил —
включается. Выключение — без подтверждения (безопасное направление).

Бэкенд **тоже** проверяет `stockfish_enabled` на каждый запрос анализа, не
только фронтенд (защита в глубину): `GET /api/stockfish/best-move` при
выключенном флаге возвращает 403, а не тихо отдаёт рекомендацию, если кто-то
дёрнет эндпоинт напрямую в обход UI.

## Движок

`python-chess` (модуль `chess.engine`, обёртка над UCI-протоколом) плюс
локально установленный бинарник `stockfish` — **не входит в репозиторий**,
ставится отдельно (`brew install stockfish` на macOS), путь задаётся
`STOCKFISH_PATH` (по умолчанию `"stockfish"`, ищется в `PATH`).

Один долгоживущий процесс движка на весь жизненный цикл бэкенда: запускается
в уже существующем `lifespan` (`app.py`) рядом с фоновой задачей ленты
переговоров, останавливается (`engine.quit()`) при shutdown. Если бинарник не
найден при старте — исключение перехватывается, процесс приложения не падает,
движок остаётся `None`; любой запрос анализа в этом случае отвечает понятной
ошибкой («Stockfish не установлен») тем же паттерном, что и недоступный
Gateway (`{"ok": False, "error": ...}`).

## Конвертация доски в FEN

Чистая функция `board_to_fen(board, side_to_move) -> str` в новом модуле
`web/backend/stockfish_client.py`. Права на рокировку и взятие на проходе
всегда `-` (в нашей упрощённой партии их и так нет — регламент их исключает),
счётчик полуходов и номер хода — фиксированные заглушки (`0` и `1`), они не
влияют на качество анализа конкретной позиции, только на служебные правила
(50 ходов, номер хода в нотации), которые Stockfish в данном случае не
использует для генерации совета по текущей позиции.

## API

- `POST /api/side-to-move {"color": "white"|"black"}` — ручной оверрайд,
  всегда доступен, обновляет `app_state["side_to_move"]`, `broadcast`.
- `POST /api/stockfish/enable {"enabled": bool}` — обновляет
  `app_state["stockfish_enabled"]`, `broadcast`. Подтверждение — ответственность
  фронтенда (как со сбросом поля/рестартом матча), бэкенд просто выполняет.
- `GET /api/stockfish/best-move` — 403 если `stockfish_enabled` ложно; иначе
  строит FEN из текущих `board`/`side_to_move`, спрашивает движок
  (ограничение по времени на ход анализа, например `movetime=1000` мс),
  возвращает `{"ok": true, "from": "e2", "to": "e4", "score": <int|null>}`
  либо `{"ok": false, "error": "..."}` (движок недоступен/битая позиция).

## Frontend

Новая панель «Анализ позиции»:
- селектор «Чей ход» (Белые/Чёрные), синхронизированный с `side_to_move`;
- переключатель «Stockfish» с описанным выше подтверждением;
- кнопка «Обновить рекомендацию» — **без** автоматического опроса на каждое
  изменение состояния (чтобы не дёргать процесс движка на каждое сообщение в
  ленте переговоров или ход таймера) — принятое упрощение v1;
- при наличии рекомендации: стрелка на SVG-доске (линия + наконечник от
  центра `from`-клетки к центру `to`-клетки, отдельным цветом, например
  оранжевым) и текст с оценкой позиции.

## Обработка ошибок

- Движок не установлен/не отвечает → `{"ok": false, "error": ...}`, UI
  показывает через уже существующий `showMessage`, кнопку обновления не
  блокирует (можно попробовать снова).
- `GET /api/stockfish/best-move` при выключенном флаге → 403 с понятным
  текстом ошибки; фронтенд физически не должен давать возможность вызвать
  этот путь, пока переключатель выключен (кнопка обновления задизейблена),
  но бэкенд не полагается только на это.

## Тестирование

- `board_to_fen`: известные позиции (начальная расстановка, простая
  произвольная позиция) → ожидаемая FEN-строка (сравнение по частям:
  расстановка фигур + буква стороны хода; служебные поля — по фиксированным
  значениям).
- `get_best_move`: мок `chess.engine` (тесты не должны требовать реально
  установленного бинарника Stockfish в окружении) — успешный ответ,
  недоступный движок → `{"ok": false, ...}`.
- `app.py`: `POST /api/side-to-move` обновляет состояние; `POST /api/move`
  автоматически переключает `side_to_move` на цвет, противоположный
  подвинутой фигуре; `POST /api/stockfish/enable` переключает флаг;
  `GET /api/stockfish/best-move` при выключенном флаге → 403 (мок
  `stockfish_client.get_best_move` не должен даже вызываться).

## Расположение в репозитории

- `web/backend/stockfish_client.py` — `board_to_fen`, `get_best_move`,
  управление процессом движка.

- `web/backend/tests/test_stockfish_client.py`.
- `web/frontend/index.html`, `styles.css`, `board.js` — панель анализа,
  стрелка на доске.
- `web/README.md` — добавить требование `brew install stockfish`

## Открытые вопросы (не блокируют реализацию)

- Пауза и досрочное завершение матча — запрошены пользователем, но
  сознательно отложены до завершения этой фичи (отдельная будущая задача по
  `match_clock`, короткий отдельный дизайн: пауза требует хранить накопленное
  время вместо наивного «сейчас минус старт», иначе часы продолжат идти во
  время паузы).
