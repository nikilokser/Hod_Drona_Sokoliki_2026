# Дизайн: модуль валидации ходов (`move_validator`)

Дата: 2026-07-30

## Контекст и цель

Регламент требует, чтобы ход выбирали исключительно LLM-агенты (шахматные движки
запрещены), а невозможный ход, выбранный LLM, — это штраф -5 и сброс таймера хода,
после трёх невозможных ходов подряд право на один ход передаётся судейскому
алгоритму (см. `CLAUDE.md`, раздел «Ключевые ограничения регламента»).

Чтобы не тратить эти попытки и не терять очки на банальных ошибках LLM (ход не по
правилам, ход под шах, промах в собственной позиции), нужен модуль, который берёт
предложенный LLM ход, проверяет его легальность по упрощённым правилам шахмат из
регламента и, если ход нелегален, возвращает понятную причину, которую можно
отдать LLM обратно для повторной попытки.

Сам цикл «спросить LLM ещё раз с этой причиной» и его встраивание в
агента-координатора (который будет жить на ноуте и принимать итоговое решение по
ходу) — это отдельная будущая задача, не входящая в scope этого модуля. Сейчас
делаем только сам модуль проверки правил.

Комплект фигур на зачётный матч — 1 Король, 1 Ферзь, 2 Слона, 2 Коня, 2 Ладьи,
8 Пешек = 16, то есть **полный стандартный шахматный набор без урезаний**.
Стартовая позиция и обычная алгебраическая нотация (`a1`-`h8`) подходят без
адаптации.

## Область действия

Включено:

- Геометрия хода для каждого типа фигуры (слайдеры с проверкой пути, конь,
  король на одну клетку, пешка вперёд/по диагонали при взятии, включая первый
  ход пешки на 2 клетки — это правило регламентом не исключено).
- Проверка того, что фигура и цвет на исходной клетке (`from`) реально совпадают
  с тем, что заявил LLM — отдельная причина отказа именно на этот случай
  («ллм думает, что там конь, а там слон»), а не просто «ход нелегален».
- Шах, мат, пат — стандартные шахматные правила (ход, оставляющий своего короля
  под шахом, нелегален; мат/пат определяются перебором всех легальных ходов
  стороны).

Явно исключено регламентом и НЕ реализуется как тип хода (поэтому не нужен
отдельный код-запрет — такие ходы отклоняются самой геометрией/логикой):

- рокировка;
- взятие на проходе;
- превращение пешки при достижении последней горизонтали (пешка, дошедшая до
  последней горизонтали, просто остаётся пешкой на этой клетке — специальной
  логики превращения нет);
- правило троекратного повторения позиции;
- правило 50 ходов.

Не входит в scope этого модуля: сеть/HTTP, вызовы LLM, цикл повторных попыток,
хранение истории партии, интеграция с доской в веб-морде.

## Данные

Плоские структуры (словари), без классов — модуль должен остаться набором чистых
функций, которые легко тестировать по отдельности и переиспользовать из будущего
агента-координатора.

```python
# board_state: только занятые клетки, ход всегда за стороной side_to_move
board_state = {
    "board": {
        "e2": ("white", "pawn"),
        "e8": ("black", "king"),
        # ...
    },
    "side_to_move": "white",  # "white" | "black"
}

# move: цвет фигуры явно не передаётся — берётся из side_to_move, но затем
# сверяется с тем, что реально стоит на from
move = {
    "piece": "knight",   # "king"|"queen"|"rook"|"bishop"|"knight"|"pawn"
    "from": "g1",
    "to": "f3",
}
```

Клетки — стандартная алгебраическая нотация `a1`-`h8` (файл `a`-`h`, ранг `1`-`8`).

## Публичный API

- `initial_board() -> board_state`
  Стандартная начальная позиция полного комплекта, ход белых.

- `validate_move(board_state, move) -> ValidationResult`
  ```python
  ValidationResult = {
      "legal": bool,
      "reason": str | None,   # None если legal=True; иначе человекочитаемая причина на русском
      "is_capture": bool,
      "captured": str | None, # тип взятой фигуры, если is_capture
  }
  ```
  Проверки выполняются по цепочке, первая же провалившаяся определяет `reason`:
  1. `from` — не пустая клетка.
  2. Фигура и цвет на `from` совпадают с `move["piece"]` и `side_to_move`.
  3. `to` в границах доски и не занята своей фигурой.
  4. Геометрия хода корректна для типа фигуры (путь свободен для слайдеров;
     конь буквой Г; пешка — вперёд/по диагонали только при взятии, включая
     двойной первый ход).
  5. После хода свой король не остаётся под шахом (симуляция хода + проверка
     атакованных клеток соперником).

- `apply_move(board_state, move) -> board_state`
  Возвращает **новое** состояние доски (без мутации входного), применяя уже
  провалидированный ход. Поведение при попытке применить нелегальный ход —
  не определено контрактом функции (вызывающий код обязан сначала вызвать
  `validate_move` и проверить `legal`).

- `is_in_check(board_state, color) -> bool`
- `is_checkmate(board_state) -> bool` — `side_to_move` под шахом и нет ни одного
  легального хода.
- `is_stalemate(board_state) -> bool` — `side_to_move` не под шахом и нет ни
  одного легального хода.

Мат/пат определяются перебором собственных фигур стороны и проверкой наличия
хотя бы одного хода, проходящего `validate_move`.

## Причины отказа (для обратной связи LLM)

Строки на русском, человеко- и LLM-читаемые, например:

- «На клетке e4 уже стоит своя фигура»
- «Ладья не может ходить по диагонали»
- «Конь так не ходит»
- «Путь до клетки перекрыт другой фигурой»
- «На клетке g1 нет коня — там другая фигура»
- «Этот ход оставляет вашего короля под шахом»

## Тестирование

Юнит-тесты (без внешних зависимостей):

- движение каждого типа фигуры, включая блокировку пути для слайдеров;
- взятия (в т.ч. попытка взять свою же фигуру — нелегально);
- пешка: одиночный шаг, двойной первый шаг, диагональ только при взятии,
  диагональ по пустой клетке — нелегально;
- шах: ход, вскрывающий своего короля (пин), — нелегально;
- мат: классические позиции (например, детский мат) — `is_checkmate` истинно;
- пат: позиция без легальных ходов, но без шаха — `is_stalemate` истинно;
- явные тесты, что рокировка/взятие на проходе/превращение отклоняются
  (`validate_move` возвращает `legal: False` для попытки такого хода — просто
  потому что это не поддерживаемая геометрия хода, отдельного кода запрета нет).

## Расположение в репозитории

Новая директория `move_validator/`:

- `move_validator/board.py` — типы данных, `initial_board()`, вспомогательные
  функции работы с клетками/фигурами.
- `move_validator/rules.py` — `validate_move`, `apply_move`, `is_in_check`,
  `is_checkmate`, `is_stalemate`.
- `move_validator/tests/` — юнит-тесты.

## Открытые вопросы (не блокируют реализацию)

- Формат подключения модуля к будущему агенту-координатору (прямой импорт vs
  что-то ещё) — решается позже, когда координатор начнёт строиться.
- Язык/формат сообщений об ошибках может потребовать доработки под конкретный
  промпт LLM-агентов, когда они появятся.
